# Купибот

Многостраничный статический сайт сервиса мониторинга Авито. Python 3.10+; для сборки и запуска не нужны сторонние зависимости, база данных, npm или внешние API. Основные тексты присутствуют в готовом HTML. JavaScript добавляет демонстрацию, фильтры, поиск и аналитику.

## Запуск

```sh
cd /workspace/sites
python3 build.py
python3 serve.py --port 3000
```

Сервер разработки слушает 0.0.0.0. Не используйте его как production-сервер. После изменения файлов повторите сборку. Создание отдельного Git worktree для облачных задач не требуется: используйте существующий checkout.

## Настройки

Все ссылки и продуктовые настройки находятся в `config.json`:

- `bot_url`: HTTPS-ссылка на существующего Telegram-бота. Пока не заполнена, кнопки открывают доступное с клавиатуры сообщение. Это локальная заглушка, а не работающая интеграция с ботом.
- `channel_url`, `support_url`, `community_url`: незаполненные ссылки скрыты.
- `domain`: HTTPS-адрес сайта без пути. После заполнения сборка добавляет canonical, og:url, абсолютные URL в sitemap и разрешает индексирование. До этого robots запрещает индексирование, sitemap пуст: фиктивного домена нет.
- `metrika_id`: числовой ID Яндекс Метрики. Без него внешний скрипт не запрашивается. Webvisor, автоматическая карта кликов и сбор введённых ссылок отключены.
- `tariffs`: название, цена, срок (`period`), описание, лимиты (`limits`), возможности (`features`), ссылка (`url`). Укажите только подтверждённые данные. Пока известны только цены 1 200 / 2 500 / 5 000 ₽; сроки не указаны.
- `platforms`: редактируемые площадки и статусы.
- `logo`: путь к оригинальному логотипу, например `/assets/kupibot_avatar_safe_circle.png`. Оригинальный файл подключён и сохранён без изменений. Положите оригинал в assets и укажите путь: он появится в подвале с object-fit: contain, без обрезки. Текстовый знак в шапке — предусмотренная компактная версия. Иконка вкладки — текстовая буква, не перерисованный логотип.

Данные публичны; не помещайте секреты в config.json. Применение настроек: `python3 build.py`.

## Материалы

Редактируйте `content/articles/*.json` и `content/devblog/*.json`. Формат: `slug`, `title`, `category`, `excerpt`, `published`, `updated`, `sections` (массив объектов `heading` / `text`). Это обычный текстовый JSON, без изменений компонентов. Даты задаёт редактор в ISO-формате YYYY-MM-DD; null скрывает поле. Неподтверждённые даты и авторы не генерируются. Для новой статьи создайте JSON по существующему примеру и пересоберите сайт. Оглавление, карточка и Article JSON-LD создаются автоматически. Содержимое экранируется: HTML в тексте не выполняется.

## Аналитика

При заполнении ID Метрика получает стандартные просмотры и источники. Цели: `telegram_click` (page, position), `tariff_select` (фиксированное название тарифа), `demo_use`, `demo_replay` (фиксированный сценарий), `scroll_depth` (25/50/75/100 один раз за просмотр), `article_read` (появление конца статьи). Поисковая строка фильтра материалов не передаётся. Демонстрация использует только фиксированные вымышленные данные, к Авито не обращается.

Покупки и продления происходят вне сайта и здесь не измеряются. В будущем можно согласовать с разработчиком бота Telegram start-параметры с фиксированными кодами источников (до 64 допустимых символов), добавить их к ссылкам и сопоставлять на сервере бота с действиями. Не передавайте личные данные или произвольные поисковые ссылки в start/события. Для точной атрибуции нужна поддержка на стороне бота; сейчас она не реализована.

## Проверки

```sh
python3 build.py
python3 tests/check_site.py
# В другом терминале должен работать serve.py.
node tests/browser.cjs
```

Для последней команды необходимы Playwright и Chromium. В текущей облачной среде они уже доступны; браузерный тест использует `/usr/bin/chromium`. На другой машине установите инструменты тестирования отдельно; сайту они не нужны.

Проверены 12 маршрутов и 404, ссылки и якоря, один H1 и метаданные, XML sitemap, 4 ширины (360/390/768/1440), отсутствие горизонтального скролла, демо и переключение сценариев, диалог без ссылки, меню, фильтры roadmap, поиск и рубрики, основной контент без JS, отсутствие JS-ошибок и запросов Метрики без ID. Скриншоты просмотрены на desktop/mobile. Метрика с реальным счётчиком и переход в реальный бот не проверялись: значения отсутствуют. Оценки Lighthouse и гарантии показателей производительности не заявляются.

## Размещение

Загрузите содержимое `dist/` на любой статический хостинг с поддержкой directory index и назначьте `404.html` страницей ошибки со статусом 404. Это не SPA: не перенаправляйте все неизвестные адреса на главную. Например, для Nginx используйте `try_files $uri $uri/ =404;` и `error_page 404 /404.html;`. Для GitHub Pages может потребоваться настройка путей при размещении в подкаталоге — текущие пути рассчитаны на корень домена. Сайт автоматически не публикуется.

Перед публикацией: добавьте оригинальный логотип, реальную ссылку на бота и домен, при необходимости ID Метрики и второстепенные ссылки; подтвердите состав тарифов или оставьте нейтральные подписи; задайте редакционные даты. После этого пересоберите сайт и повторите проверки. Сайт не содержит парсера, оплаты или кабинета.
